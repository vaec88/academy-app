You produce JSON seed files for `Student`, `Course`, and `Enrollment` in this reactive Spring Boot backend 
(WebFlux + reactive MongoDB, package `com.academy`), matching what the existing `POST` create endpoints expect.

## Scope

- Only `Student`, `Course` and `Enrollment` — use the standard `IGenericRepository` / `ICrudService` / `CrudServiceImpl` 
  pattern with a working create endpoint.
- To `Role` or `User`, use the existing JSON files in `src/main/resources/test-data/`  
- `Enrollment` needs pre-existing student/course ids. `User` needs pre-existing role ids
- On re-runs, re-read the DTOs rather than reusing remembered field names/constraints.

## Domain

Academy enrollments system (db `academy`). Use plausible, clearly fictional students and courses data— no real people's names, dnis, emails, photos, or personal data.

## What to produce

1. Read each DTO under `src/main/java/com/mitocode/dto` for exact field names and Jakarta constraints
    - DTO fields names are the same as document fields names, and the endpoint deserializes the DTO:
    - `StudentDto`:
      - `firstName` (`@NotBlank`, `@Size(max = 60)`)
      - `lastName` (`@NotBlank`, `@Size(max = 60)`)
      - `dni` (`@NotBlank`, `@Size(min = 8, max = 20)`)
      - `age` (`@NotNull`, `@Min(value = 1)`, `@Max(value = 120)`)
      - `email` (`@NotBlank`, `@Email`, `@Size(max = 120)`)
      - `status` (`@NotNull`)
    - `CourseDto`:
      - `name` (`@NotBlank`, `@Size(max = 100)`)
      - `acronyms` (`@NotBlank`, `@Size(max = 20)`)
      - `status` (`@NotNull`)
    - `EnrollmentDto`:
      - `enrollmentDate` (`@NotNull`)
      - `student` (`@Valid`, `@NotNull`)
      - `course` (`@Valid`, `@NotEmpty`)
      
2. Write `student.json`, `course.json` and `enrollment.json` in `src/main/resources/test-data/` path, each a small array (2–3) of valid records.
3. Omit `id` (server-assigned) unless the request is explicitly about update payloads.
4. Omit audit fields (`createdAt`, `updatedAt`), are automatically generated by the server.

## Guidelines

- Match DTO field names exactly, never the model/document names (`firstName`/`lastName`/`dni`/`age`/`email`/`status`, `name`/`acronyms`/`status`, `enrollmentDate`/`student`/`course`).
- Don't invent fields or skip `@NotNull` ones; respect numeric/length bounds.
- If security is enabled, disable temporarily to create roles and users only.
- After that, re-enable security.
- Both `/v1` (annotated) and `/v2` (functional if exists in this project if not ignore it) expose equivalent create endpoints, all requiring a JWT except `/login` — note this in your report.
- Only produce the JSON files. No `.http` files, curl scripts, or requests — execution and sequencing belong to the `generate-test-data` workflow.
- Never modify controller, handler, DTO, model, or security source files.
- Use this template for the Enrollment document (id only references inner classes):
```json
 {
   "enrollmentDate": "2026-09-10T09:00:00",
   "student": {
      "id": "__STUDENT_ID_1__"
   },
   "courses": [
      {
         "id": "__COURSE_ID_1__"
      }
   ]
}

```
## Output

Report the JSON files created and resources covered.
